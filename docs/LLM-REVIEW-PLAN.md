# 赛后复盘（LLM 驱动）方案

## 一、目标
每场 TI（或重大比赛）结束后，自动产出**有观点、有数据、可分享**的赛后复盘图文，挂在站点首页/复盘页，形成赛事内容栏目（和周报互补，一个「数据工具」一个「赛事话题」）。

## 二、核心架构：生成时用 LLM，发布静态文件
纯静态站点必须遵守：**LLM 在「内容生成阶段」调用（Actions 里跑一次），访问者看到的是已生成的静态 HTML/MD**，绝不在浏览器里调 LLM（慢、贵、无 key）。

```
[GitHub Actions 手动/定时触发]
        │
        ▼
1. 拉比赛数据  ── OpenDota /matches/{id}（单场完整：radiant_win、
                    duration、players[]：英雄/装备/伤害/GPM/XPM/KDA/等级）
        │
        ▼
2. LLM 生成复盘 ── 把比赛数据摘要 + 系统提示词发给 LLM
                   产出 markdown（MVP/关键转折/数据亮点/认知差联动）
        │
        ▼
3. 写静态文件  ── site/data/reviews/{date}-{match}.md
                   （或首页区块）+ 可选长图
        │
        ▼
4. commit + push → 部署 workflow → 上线
```

## 三、数据源评估（关键风险）
| 源 | 数据 | 可靠性 | 问题 |
|---|---|---|---|
| **OpenDota /matches/{id}** | 单场完整数据 | 中低（实测常 522） | 服务端不稳；拿不到「解说/战术分析」这类高层信息 |
| **/proMatches** | 职业比赛列表 | 中低 | 同上；无赛后叙事 |
| **Liquipedia / 官方** | 赛程、对阵、比分 | 中 | HTML 解析 + 可能反爬 |
| **LLM 自身知识** | 战术、版本、队伍背景 | 高 | 无实时数据，需喂数据；要注意幻觉 |

**结论**：LLM 复盘必须「**数据为骨、LLM 为肉**」——把 OpenDota 的结构化数据（谁赢了、谁伤害最高、谁 GPM 爆表、选了什么认知差英雄）喂给 LLM，让 LLM 基于真实数字写分析，而不是让它凭空编。**数据源失败要能降级**（保留骨架文案，标注"数据缺失"）。

## 四、LLM 如何接入 Actions（现成的无后端方案）
GitHub Actions 里可以直接调 LLM API（OpenAI/DeepSeek 等），需要一个 **API key（repo secret）**。选型：
- **DeepSeek**（便宜、中文好、写游戏分析够用）→ 推荐，和站点中文调性一致
- OpenAI GPT 也行，贵些
- 也可以**复用你现有的模型路由**（如果 OpenClaw 网关能对外提供 key/HTTP 接口，Actions 直接 curl 它）

**成本估算**：一场比赛数据文本 + 提示词约 2-3K tokens，单场几毛钱，TI 整个赛事几十场也就几块钱，可忽略。

## 五、复盘内容模板（LLM 输出结构）
每个复盘固定章节，保证质量稳定：
1. **一场战报**：对阵双方、胜负、比分、时长、关键人头
2. **MVP 选手**：基于真实数据（伤害/GPM/参战率）给，LLM 只做归纳不编
3. **关键转折点**：LLM 结合数据推断（如"某队 30 分钟团灭后经济被拉开"）
4. **数据亮点**：最高伤害/GPM/KDA、盲区数字，标红展示
5. **认知差联动**：本场出现的「认知差英雄」→ 链接到站点周报（打通两个栏目）
6. **版本视角**：本场所用阵容对当前版本的理解

> 前端展示复用现有周报的**分享工具条（二维码/下载长图/复制链接）**，复盘也能一键分享。

## 六、站点结构改动
- 首页加一个「**赛事复盘**」区块（最新 1-2 场 + 跳转全部）
- 新增 `reviews.html` 复盘列表页 + 每场复盘详情（或用 markdown 渲染）
- `site/data/reviews/` 存复盘 markdown，`reviews/*.md` 编译成静态页或前端直接 fetch MD 渲染

## 七、触发方式（分两档）
- **手动**（推荐先用）：我（AI 助手）赛后给你比赛 id，你在 Actions 点「Run workflow」→ 传比赛 id 参数 → 生成复盘。可控、省成本
- **自动**（进阶）：定时扫 `/proMatches` 检测新结束的 TI 比赛 → 自动触发。省人工但费 token、且 OpenDota 不稳时误报多

## 八、实施步骤（建议顺序）
1. **跑通最小闭环**：一个 workflow，输入比赛 id → 拉 OpenDota 单场数据（成功时）→ 调 DeepSeek → 输出 markdown 存 site/data/reviews/ → 部署
2. **前端落地**：首页赛事复盘区块 + reviews 列表/详情页 + 分享工具条
3. **降级与质量**：数据失败时保留骨架；LLM 输出加"AI 生成，数据来自 OpenDota"标注
4. **内容运营**：TI 期间每周赛做 2-3 场重点复盘，配合周报引流

## 九、风险与对策
| 风险 | 对策 |
|---|---|
| OpenDota 522/限流 | 脚本重试+降级；备用数据源；失败不阻断页面 |
| LLM 幻觉（编比分/选手） | 只喂真实数据；提示词强制"严格基于给定数据"；输出后脚本校验关键数字 |
| API key 泄露 | 放 repo secrets，不回显、不进前端 bundle |
| 内容版权/准确性 | 标注"AI 生成 + 数据来源"，赛后人工可改 |
